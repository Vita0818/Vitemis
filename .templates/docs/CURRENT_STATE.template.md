# CURRENT_STATE.template.md

> 本模板定义 `docs/CURRENT_STATE.md` 应记录的内容。填充后删除本说明块。

# CURRENT_STATE

最近一次自查日期：{{YYYY-MM-DD}}

## 当前真实状态总览

用一段或一组要点说明项目**当前**的真实状态：

- 项目处于什么阶段（草稿 / MVP / 内测 / 发布 / 维护）。
- 哪些能力已真实落地并可用。
- 哪些能力只是代码就绪但未验证、未发布或被开关挡住。
- 哪些能力明确未实现或已废弃。

> 注意：状态必须以当前源码为准，不能只抄旧文档。代码与文档冲突时，以源码为准并在此记录冲突。

## 已有能力

逐项列出已落地的能力。每项标注：

- 能力名称
- 入口文件 / 关键类型
- 是否有测试覆盖
- 是否有手动验证记录
- 真机/实际环境是否验证过

## 未完成 / 进行中

逐项列出未完成项。每项标注：

- 名称与目标
- 当前进度（代码就绪 / 部分实现 / 未开始）
- 阻塞原因
- 下一步动作

## 风险

列出已知风险：

- 技术风险（架构、性能、安全、兼容性）
- 文档风险（文档与源码漂移、过期结论）
- 验证风险（缺真机、缺配对设备、缺凭据等）

## 工作区状态

记录本轮自查时 `git status --short` 的关键内容分类：

- 用户已有未提交改动（不得覆盖）
- 本轮新增改动
- 未跟踪文件

## 文档与源码冲突

如发现 `docs/` 文档与当前源码、配置、测试或脚本冲突，逐条列出：

- 冲突位置（文档文件 + 行 / 源码文件 + 行）
- 冲突内容
- 采用源码为准的原因
- 建议后续如何修正文档
